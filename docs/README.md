# Полное руководство по ConnectMVKBulder

Подробное руководство по библиотеке-обёртке МВК01 (Modbus/TCP, C#/.NET 8).
Главы идут **по возрастанию сложности**: от первого подключения до собственного транспорта
и справочника API. Каждая глава самодостаточна, но ссылается на предпосылки.

Если нужен быстрый обзор — начните с [корневого README](../README.md);
это руководство предназначено для последовательного изучения и как справочник.

## Маршруты обучения

Базовый курс (первый день):

```
01 → 02 → 07b → 11 (рецепты 1–3, 9)
```

Сервис/приложение с несколькими устройствами:

```
01 → 02 → 03 → 05 → 06 → 08 → 10 → 11
```

Уставки и тревоги:

```
15 → 11 (рецепты 21–22) → 08
```

Глубокое погружение в протокол и регистры:

```
04 → 07a → 12a → 12b
```

Тесты и CI:

```
09 (при необходимости → 06 для своего middleware)
```

Поиск решения проблемы:

```
13 → 08 → при необходимости 04 (сырая диагностика)
```

## Как читать примеры

- В репозитории три готовых примера:
  `samples/Mvk.Sample.Console` (DI, свой middleware, обзор устройства и режим `watch`),
  `samples/Mvk.Sample.Polling` (минимальный опрос СКЗ 10…1000 Гц каждые 0,5 с)
  и `samples/Mvk.Sample.Alarms` (JSON-уставки и реакции на тревоги).
- Все примеры — на C# (net8.0), асинхронный стиль (`await`), с `CancellationToken`.
- Ссылки на проекты: `Mvk.Modbus` (транспорт, пул, пайплайн) и `Mvk.MVK01` (типизированный слой).
- Примеры, работающие с реальным устройством, используют адрес `10.20.0.211:502`
  (SlaveId 1, ПО 1.0.67.1). На реальном устройстве примеры выполняют **только чтение**;
  запись, `SaveConfiguration` и `Reboot` — только с явного разрешения.
- Эмулятор `Mvk.Testing` позволяет повторять все примеры без железа (см. главу 09).

## Соглашения обозначений

| Обозначение | Значение |
|---|---|
| `A` | базовый адрес блока канала (например, канал 1 → `0x2000` для расчётных параметров) |
| `N` | номер расчётного параметра (1–184) в адресации `0x4000 + (N−1)×16` |
| `0x…` | адрес или значение в шестнадцатеричном виде |
| «регистр» | 16-битный регистр Modbus; длины в документации устройства указаны в байтах (4 байта = 2 регистра) |

## Известные расхождения с документацией устройства

- Пример адреса для N=48 в `MVK01_registers.txt` (`0x41F0`) ошибочен; формула даёт
  **0x42F0** — подтверждено на реальном устройстве (глава 07a).
- Строки каналов (единицы измерения, серийные номера датчиков) хранятся с обратным
  порядком байт внутри 4-байтных слов; кодировка cp1251 (глава 07a).
