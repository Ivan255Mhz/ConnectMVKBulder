# AGENTS.md — правила работы с проектом ConnectMVKBulder

Библиотека-обёртка для устройства МВК01 (Modbus/TCP, C#/.NET).
Документация для пользователей: [README.md](README.md) (быстрый старт) и
[docs/README.md](docs/README.md) (полное руководство по главам).
Roadmap и ключевые решения: [PLAN.md](PLAN.md). Карта регистров: [MVK01_registers.txt](MVK01_registers.txt).

## Команды

```powershell
dotnet build ConnectMVKBulder.sln        # сборка
dotnet test                              # тесты
dotnet run --project samples\Mvk.Sample.Console   # пример
```

## Тестовое оборудование

- Реальное МВК01 доступно в сети: **10.20.0.211:502** (SlaveId 1, BigEndian по умолчанию).
- Транспорт и карту регистров проверять smoke-тестом на реальном устройстве, когда оно доступно;
  эмулятор `Mvk.Testing` — для автоматических юнит-тестов и CI без железа.
- На реальном устройстве не выполнять запись регистров, Save/Reboot без явного разрешения.
- Проверка доступности: `Test-NetConnection 10.20.0.211 -Port 502`.

## Конвенции кода

- TFM `net8.0`, `Nullable enable`, `ImplicitUsings enable` (задано в `Directory.Build.props`).
- Пространства имён блочные (как в `Complex.Modbus`), Allman (фигурные скобки на новой строке).
- Приватные поля — `camelCase` без подчёркивания; публичные члены — `PascalCase`.
- XML-документация на русском для публичных типов и членов.
- Логирование — только `ILogger<T>` через DI. Статический Serilog в библиотеках не использовать.
- Асинхронность: async-first, `CancellationToken` во всех публичных асинхронных методах, суффикс `Async`.
- Исключения: свои типы (`MvkModbusException` + `MvkErrorKind`), ошибки транспорта не глотать
  и не возвращать пустые массивы.
- NModbus использовать только внутри проекта `Mvk.Modbus` (в остальных проектах — интерфейсы библиотеки).
- Не менять архитектуру и не добавлять NuGet-пакеты без необходимости.
- Новый публичный API обязан иметь простой вход: значения по умолчанию на все параметры
  и один вызов для типового сценария (см. «Принципы простоты» в PLAN.md).

## Структура

```
src/Mvk.Modbus/       — транспорт, пул, пайплайн, конфигурация, DI
src/Mvk.MVK01/        — типизированная карта регистров и фасад МВК01
tests/Mvk.Testing/    — эмулятор Modbus-slave для тестов
tests/*.Tests/        — юнит- и интеграционные тесты
samples/              — примеры использования
docs/                 — полное руководство (главы по возрастанию сложности)
```

## Ветки

- Основная ветка разработки — `dev`. Вся работа ведётся в отдельных ветках от `dev`
  (имя: `task/<краткое-имя>` или `этап-N`).
- После успешно выполненной задачи (сборка и тесты зелёные) — merge в `dev` и push в `dev`.
- В `main` изменения попадают только по явному запросу.
- Если задача не завершена — изменения остаются в ветке задачи, без merge в `dev`.

## Коммиты

- Сообщения на русском, короткие и по смыслу (например: `Этап 1: ядро Mvk.Modbus`).
- Один этап из PLAN.md — один-два коммита; после изменений сборка и тесты должны быть зелёными.
- Отмечать выполненные пункты в PLAN.md (`[x]`).
